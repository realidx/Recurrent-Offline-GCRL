\section{Introduction}
Many difficult prediction problems are better viewed as iterative inference than as one-shot regression. Rather than mapping an input directly to an answer in a single feedforward pass, a model can maintain a latent state, repeatedly revise it, and expose deeper computation through repeated application of a shared update rule. This idea appears in recurrent-depth sequence models such as Universal Transformers, adaptive computation methods, implicit fixed-point models, and recurrent reasoning systems that solve supervised tasks through repeated latent refinement \citep{universal_transformer, act, deq, recurrent_relational_networks, energy_diffusion, hrm, trm, urm}. These developments suggest a broader architectural question: can iterative refinement also serve as a useful computation principle for reinforcement learning?

Recent architecture work shows that network design can substantially affect RL performance. Increasing depth, width, regularization, or residual feedforward capacity has improved several online and self-supervised RL settings \citep{thousand_layers, bro, simba}. However, offline goal-conditioned RL (GCRL) appears to be a different regime. The same depth-scaling study that reports large online goal-reaching gains also finds that directly scaling feedforward depth on offline GCRL does not reliably help \citep{thousand_layers}. This contrast suggests that the missing ingredient may not be capacity alone. In offline GCRL, extra computation must be useful for a specific fixed-data inference problem: deciding which goals are reachable, which behavioral fragments can be stitched, and which learned signals can safely support policy extraction.

This makes offline GCRL a natural stress test for iterative refinement. The agent receives only a fixed dataset of trajectories and must learn goal-reaching behavior without further interaction. Benchmarks such as OGBench are designed to expose long-horizon reasoning, trajectory stitching, state-goal generalization, and policy-extraction difficulties under this fixed-data constraint \citep{ogbench}. Recent analyses suggest that the bottleneck in offline GCRL is not unique: value learning, policy extraction, and generalization can all limit offline RL and offline GCRL depending on the method and task \citep{ogbench, value_bottleneck}. A recurrent refinement architecture is attractive in this setting because it changes how computation is used: instead of making a single deeper feedforward pass, it repeatedly updates a latent representation before the algorithm consumes the resulting value, score, or policy signal.

This paper studies iterative refinement as an architectural bias for offline GCRL. We ask whether replacing a single feedforward computation with repeated latent refinement can improve the learned objects used by offline goal-conditioned algorithms. To instantiate the idea, we build recurrent modules using standard stabilizing components from modern deep networks, including SwiGLU updates, recurrent step embeddings, LayerNorm, and LayerScale \citep{shazeer_glu, universal_transformer, layer_norm, layerscale}. We then evaluate refinement across several algorithmic settings, while using Contrastive RL (CRL) as the main diagnostic case because its learned score is especially exposed: CRL trains a goal-conditioned compatibility function and then trains the actor to choose actions that score well under that function \citep{crl}. This lets us ask not only whether refinement improves offline GCRL, but also how it changes the learned signal that policy extraction relies on.

The paper makes four contributions. First, it introduces iterative latent refinement as an architectural principle for offline GCRL and instantiates it in recurrent network modules for goal-conditioned learning. Second, it shows that refinement gives its clearest gains on stitching-heavy OGBench tasks, where long-horizon reachability judgments are central. Third, it provides diagnostic evidence, especially in CRL, that the gain is mediated by a more actor-usable value signal rather than by a uniformly larger raw margin or a better global graph-distance model. Fourth, it tests the scope of the idea through iteration-depth studies, ablations, feedforward capacity controls, actor-side replacements, other offline GCRL algorithms, and an online CRL extension.

\section{Related Work}
Many areas of machine learning have recently explored architectures that allocate computation through repeated latent updates rather than a single feedforward pass. Universal Transformers apply recurrence over depth with shared transition functions and adaptive computation \citep{universal_transformer, act}, while Deep Equilibrium Models formulate prediction as convergence to an implicit fixed point \citep{deq}. A broader family of recurrent and iterative reasoning methods similarly performs multiple rounds of latent correction before producing a final prediction \citep{recurrent_relational_networks, energy_diffusion}. More recent systems such as HRM, TRM, and URM have renewed interest in this direction by showing that compact recurrent computation can be effective on supervised reasoning tasks \citep{hrm, trm, urm}. Reinforcement learning has also seen growing interest in architecture and scaling. Recent work has improved online RL agents by increasing network depth or width, adding residual structure, or otherwise strengthening feedforward actor-critic backbones \citep{thousand_layers, bro, simba}. These results suggest that value-function architecture can be an important factor in control performance. However, offline goal-conditioned RL poses a different scaling problem. In this setting, conventional feedforward architecture changes do not necessarily yield consistent gains, because the agent must infer goal reachability from a fixed dataset rather than repair value errors through additional interaction.

Offline goal-conditioned RL is particularly challenging because it combines long-horizon reasoning with the distributional constraints of offline learning. OGBench was introduced to study these difficulties through tasks that require stitching across trajectories, generalization over state-goal pairs, and robust policy extraction from learned value estimates \citep{ogbench}. Recent analyses further suggest that the main bottleneck in offline GCRL is not unique: value learning, policy extraction, and generalization can all limit performance depending on the algorithm and task \citep{ogbench, value_bottleneck}. 

Existing offline GCRL algorithms address these challenges from several directions. Contrastive RL learns a goal-conditioned compatibility score and trains the actor to optimize that score, providing a simple non-hierarchical actor-critic formulation \citep{crl, ogbench}. Hierarchical methods such as HIQL introduce temporal abstraction to improve long-horizon goal reaching \citep{hiql}. Other recent approaches, including SAW-style methods, focus on improving policy extraction or actor-side goal-conditioned learning under fixed datasets \citep{saw}. These directions are complementary to ours, as our work targets the value-learning side of this picture.


\section{Preliminaries}
\label{sec:preliminaries}
\paragraph{Offline goal-conditioned RL}
We consider an offline goal-conditioned Markov decision process with state space $\mathcal{S}$, action space $\mathcal{A}$, transition kernel $P$, and goal space $\mathcal{G}$. The learner is given a fixed dataset of trajectories $\mathcal{D}=\{\tau^{(n)}\}_{n=1}^{N}$, with $\tau=(s_0,a_0,s_1,\ldots,s_T)$, and receives no further environment interaction during training. Given an initial state and goal $g$, the objective is to learn a goal-conditioned policy $\pi(a\mid s,g)$ that maximizes the discounted goal-reaching return
\(
J(\pi)=
\mathbb{E}_{g \sim p(g),\, \tau \sim p^{\pi}(\tau \mid g)}
\left[
\sum_{t=0}^{\infty} \gamma^t r_g(s_t,a_t,s_{t+1})
\right],
\)
where $r_g$ is the sparse goal-reaching reward or its environment-specific analogue. During training, goals are sampled from the dataset, with future states providing positive reachability supervision and other dataset states providing contrastive comparisons.

\paragraph{Contrastive RL}
Contrastive RL (CRL) learns a goal-conditioned compatibility score and then extracts a policy from that score \citep{crl}. We write the critic as $f_{\phi,\psi}(s,a,g)$ and the actor as $\pi_\theta(a\mid s,g)$. CRL can be written as a binary-NCE objective that contrasts a future goal $g$ against a random goal $g^-$ \citep{ma_collins_binary_nce, crl}:
\begin{equation}
\mathcal{J}_{\mathrm{CRL}}(f)
=
\mathbb{E}_{(s,a)\sim p_{\mathcal{D}},\,g\sim p_{\mathcal{D}}^{\mathrm{future}}(\cdot\mid s,a),\,g^-\sim p_{\mathcal{D}}}
\left[
\log\sigma(f(s,a,g))+\log(1-\sigma(f(s,a,g^-)))
\right].
\end{equation}
In our experiments, the score is parameterized as a scaled inner product
\(f_{\phi,\psi}(s,a,g)=\phi(s,a)^\top\psi(g)/\sqrt{d}\). Following the OGBench reference implementation, we estimate the negative of this objective with an in-batch sigmoid BCE loss: for logits $\ell_{ij}=f_{\phi,\psi}(s_i,a_i,g_j)$, diagonal entries are positives and off-diagonal entries are negatives \citep{ogbench},
\begin{equation}
\mathcal{L}_{\mathrm{critic}}(\phi,\psi)
=
\frac{1}{B^2}\sum_{i=1}^{B}\sum_{j=1}^{B}
\mathrm{BCE}\!\left(\ell_{ij}, \mathbf{1}[i=j]\right).
\end{equation}
For policy extraction, continuous-action CRL uses the DDPG+BC objective from OGBench, replacing $Q$ with the learned CRL score:
\begin{equation}
\mathcal{J}_{\mathrm{actor}}(\pi_\theta)
=
\mathbb{E}_{(s,a)\sim p_{\mathcal{D}},\,g\sim p_{\mathcal{D}}(\cdot\mid s)}
\left[
f_{\phi,\psi}(s,\pi_\theta^\mu(s,g),g)
+ \alpha \log \pi_\theta(a\mid s,g)
\right],
\end{equation}
where $\pi_\theta^\mu(s,g)$ is the mean action of the policy \citep{td3bc, ogbench}. Thus policy extraction depends directly on the learned score while remaining regularized toward behavior support. This direct score-to-actor interface is why CRL is our main diagnostic setting for studying how refinement changes value learning. We use the same CRL setup as OGBench to keep the comparison straightforward.



\section{Recurrent Latent Refinement}
\label{sec:architecture}
Our goal is to test iterative refinement as cleanly as possible, not to introduce a heavily engineered backbone. We therefore use a minimal recurrent module that can replace a feedforward block while keeping the surrounding algorithm, losses, replay data, and optimization procedure unchanged. Given an input representation $x$, the module initializes a latent state $h^{(0)}$ and refines it for $K$ steps with a tied update rule. The same parameters are reused at every refinement step, so additional computation comes primarily from recurrence rather than from adding an independent stack of layers.

The refinement block combines four standard components. First, we use pre-layer normalization to keep the repeatedly updated latent state on a stable scale \citep{layer_norm}. Second, we add a learned step embedding $E_k$, which lets a shared recurrent block distinguish early and late refinement steps, analogous to depth or recurrence-position information in recurrent-depth transformers \citep{universal_transformer}. Third, the update uses a SwiGLU transformation, providing a simple gated nonlinear channel update without introducing attention or task-specific machinery \citep{shazeer_glu}. Finally, the residual update is multiplied by a small LayerScale coefficient $\alpha_k$, which controls the magnitude of each refinement step and stabilizes repeated residual computation \citep{layerscale}. In compact notation, one refinement step is
\begin{equation}
h^{(k+1)}
=
h^{(k)}
+
\alpha_k W_o\,\mathrm{SwiGLU}\!\left(\mathrm{LN}(h^{(k)})+E_k\right),
\qquad k=0,\ldots,K-1.
\end{equation}
Only the step embeddings and LayerScale coefficients are step-specific; the update weights are shared across refinement steps. This design makes the architectural hypothesis explicit: offline GCRL may benefit from repeatedly revising the latent value or policy representation before it is consumed by the algorithm. The exact insertion point, hidden dimension, refinement depth, and algorithm-specific instantiations are described in the experimental setup, so the method section only specifies the shared refinement principle.



\section{Experiments}
\subsection{Experiment Setup}
\paragraph{Environments and evaluation protocol}
We evaluate on OGBench \citep{ogbench}, a benchmark designed specifically for offline goal-conditioned RL. In this setting the agent receives a fixed dataset of trajectories and must learn to reach new evaluation goals without any additional environment interaction. OGBench provides standardized datasets and multiple held-out state-goal evaluation pairs for each task, making it useful for testing long-horizon reachability, trajectory stitching, state-goal generalization, and policy extraction from offline data. The benchmark spans locomotion and manipulation domains: locomotion tasks require simulated agents to navigate mazes of different sizes and dataset types, while manipulation tasks require reaching object configurations or compositional scene goals. Following the benchmark protocol, we report average success over the five OGBench evaluation tasks for each dataset, with 50 episodes per task.


\paragraph{Algorithms and architecture}
We study recurrent latent refinement as an architecture-level replacement inside existing offline GCRL algorithms, rather than as a new loss or data-generation procedure. Our experiments include CRL, HIQL, and SAW as the main algorithmic settings, with GCIQL and QRL used as additional value-learning checks where available. These methods cover complementary regimes: CRL exposes a contrastive state-action-goal critic, HIQL and SAW represent hierarchical or subgoal-based policy-extraction approaches for long-horizon tasks, and GCIQL/QRL provide additional value-learning baselines. In each comparison, the recurrent variant replaces the relevant MLP value or critic backbone with the tied refinement module from Section~\ref{sec:architecture}. The surrounding algorithm is otherwise held fixed, including the actor architecture, replay data, goal sampling, losses, batch size, optimizer, and evaluation protocol. Exact hyperparameters and insertion points are reported in the appendix. Unless otherwise noted, the default recurrent module uses four refinement steps; Section~\ref{sec:depth} studies this choice directly.

\subsection{Why Is the Recurrent Critic Better?}
End-task success alone does not explain what the recurrent critic changes. This subsection therefore uses CRL as the mechanism analysis setting because CRL exposes the critic signal most directly. Our diagnostic experiments focus on three state-based AntMaze tasks that play different roles in the analysis: \texttt{antmaze-medium-stitch} (AMS), a clean positive case; \texttt{antmaze-large-stitch} (ALS), a harder long-horizon stitching case; and \texttt{antmaze-giant-navigate} (AGN), a boundary case with sparser useful stitching signal. Unless stated otherwise, the diagnostic comparison is the default MLP CRL critic against the four-step recurrent CRL critic.

A central challenge in analyzing architectural changes in reinforcement learning is that final performance can conflate value learning, policy optimization, data coverage, and evaluation variance. CRL provides a cleaner diagnostic setting because the learned score $f(s,a,g)$ is trained explicitly by the contrastive objective and then used directly in the DDPG+BC actor objective. Changes to the critic therefore appear at the policy-extraction interface, rather than only through an indirect bootstrapping target.

Concretely, CRL learns a compatibility score for state-action-goal triples. A dataset transition paired with a future goal from the same trajectory is a positive pair, while pairing the same transition with another sampled goal gives a negative pair. Let $q^+=f(s,a,g)$ and $q^-=f(s,a,g^-)$ denote these matched and mismatched scores. If recurrent refinement changes the critic in a useful way, it should make this positive-versus-negative signal easier for the actor to use, not merely change the final success number.

We use this structure to ask three mechanism questions: whether the recurrent critic separates matched and non-matched goals more reliably, whether the actor can use the resulting score while remaining near behavior support, and whether the gains are simply explained by better maze-distance geometry. For critic discrimination, we report the raw margin $\mathbb{E}[q^+-q^-]$, ranking accuracy $\Pr[q^+>q^-]$, and normalized separation
\[
\frac{\mathbb{E}[q^+-q^-]}{\sqrt{\mathrm{Var}(q^+) + \mathrm{Var}(q^-) + \epsilon}}.
\]
For actor usability, we use the fact that the DDPG+BC actor is trained to choose actions that score well under the CRL critic while remaining behavior-regularized. We therefore compare critic scores on actor and dataset actions through $q_\Delta=\mathbb{E}[f(s,\pi(s,g),g)]-\mathbb{E}[f(s,a_{\mathcal{D}},g)]$, the fraction of states where the actor action is preferred, and policy--behavior deviation. Finally, graph-distance correlations are included only as a caveat: they test whether recurrence is merely learning a better shortest-path surrogate.

\subsection{Iterative Refinement Creates a Threshold Effect}
\label{sec:depth}
The previous subsection shows that the recurrent critic changes the CRL signal. We next ask whether this effect actually requires iteration. A one-step recurrent block is an important control: it changes the critic architecture, but it cannot repeatedly revise the latent representation. We therefore sweep the number of refinement steps $K$ on \texttt{antmaze-medium-stitch}. The result is a clear threshold. One refinement step is not enough to explain the gain; performance enters the high-success regime only after the critic is allowed to refine its representation multiple times.

\subsection{Matched Parameter and Computation Comparison}
Because the paper is architectural, fairness controls are mandatory. The cleanest capacity-control environment is \texttt{antmaze-large-stitch-v0}. The recurrent critic should be compared against the default MLP critic, a wider MLP, and a deeper MLP. The feedforward controls should preserve the same basic MLP recipe as CRL's default critic: GELU activations, layer normalization, and no residual connections. The wider and deeper controls are chosen by matching critic parameter count as closely as possible to the recurrent critic, rather than by arbitrary scaling.

For the current recurrent target, parameter matching yields two reasonable controls: a wider MLP with hidden sizes \texttt{688-688-688} and a deeper MLP with hidden sizes \texttt{512-512-512-512-512}. The former is within 0.37\% of the recurrent critic's parameter count, and the latter is within 0.19\%. These should be the primary fairness baselines. Compute should be reported separately using measured wall-clock statistics such as \texttt{time/step\_time}. If exact compute matching would require pathological plain MLPs, the paper should instead present the nearest valid feedforward controls together with wall-clock or anytime performance curves.

\subsection{Actor-Side Recurrence for the Sake of Completeness}
The actor-side story should be presented as a separate failure mode. If recurrent critics help because they refine the goal-conditioned learning signal, then moving recurrence to the actor need not help much and may even hurt. This is an important negative result because it argues against the generic claim that ``recurrent networks are better everywhere.'' The clean comparison here is baseline CRL, recurrent critic only, recurrent actor only, and critic-plus-actor recurrence on one stitching task and one lower-gain task. The expected result is that the critic-side replacement dominates, while actor-side recurrence produces smaller, inconsistent, or negative gains.

\subsection{Online Extension}
The final experiment block should show that the core mechanism is not purely an artifact of offline training. A compact online CRL experiment can ask whether the same recurrent critic still helps when the data distribution is no longer fixed. The claim should remain modest: not that recurrence solves online exploration in general, but that the same critic-side architectural bias continues to be useful when CRL is trained online. This section can be short, but it helps broaden the paper beyond a purely offline curiosity.
